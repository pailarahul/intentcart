IntentCart: Online Purchase Intention

Can browsing behaviour predict whether a shopping session ends in a purchase? We compare simple baselines with logistic regression and tree-based models on 12,330 e-commerce sessions. We also ask how much of the signal comes from one suspicious feature, PageValues.

1Question and framing

What exactly is predicted, for whom, and when.

QuestionGiven what a visitor did during one session on an online store, can we predict whether the session ended in a purchase? Which kinds of model do this better than simple baselines, and where do they fail?
One rowOne browsing session. The dataset was built so that each session belongs to a different user, so there are no repeated visitors to leak across splits.
TargetRevenue = 1 if the session included a transaction, else 0. Positive rate: ( of ).
When the prediction is madeAt the end of a session. Every feature is a whole-session aggregate (total pages, total time, average exit rate). A realistic use is deciding, once a visit ends, which non-buyers resemble buyers and are worth a reminder or offer. This is not a real-time, mid-session predictor. The dataset has no time-stamped clicks, so we cannot evaluate one.
Information available thenPage counts and durations by page type, bounce and exit rates, month, special-day proximity, weekend, visitor type, and anonymised OS, browser, region and traffic-source codes. PageValues is the problem column. Google Analytics computes it from the revenue of sessions that passed through the same pages, so it can carry information about the outcome. We therefore run two feature settings:

Setting A · All features

Optimistic upper bound. Kept to show how much a single possibly-leaky feature inflates the score.

Setting B · Without PageValues main claim

Only behavioural and context variables. Our conclusions rest on this setting.

Limits of the claimPredictive association within one retailer's data for one year. We make no causal claims ("long product-page time causes buying"), and the results may not transfer to other stores or periods (see §9 and §10).

Quality checks and what we found

  • Duplicates: there are extra copies ( rows in duplicate groups). All of them are one-page bounce sessions with zero duration and no purchase. With so few distinct values, different visitors who land on a page and leave produce identical rows. We therefore treat them as real traffic and keep them. §9 shows that removing them changes the test PR-AUC by only about 0.01.
  • PageValues leakage: sessions with PageValues > 0 buy of the time, against when it is 0. Google Analytics assigns a page value from the revenue of sessions that reached a transaction after viewing that page. So most buying sessions (81% here) have pages with value, partly because they bought. Its exact computation window is unknown to us, so we cannot rule leakage in or out. Hence the two settings.
  • Seasonality and coverage: purchase rates range from (Feb) to (Nov). Two months are missing, so any month effect is specific to this calendar.
  • Visitor type: new visitors buy more often () than returning ones (). Returning visitors are 86% of the data.
  • Skew and outliers: durations reach many hours. We keep these values, since they are plausible idle tabs, and compress them with log1p for the linear model instead of deleting them.

4Baselines and models

From trivial to flexible. More complex is not assumed to be better. Each model must beat the simpler one under the same protocol.

Majority class baseline

Predicts "no purchase" for everyone (probability = training prevalence).

The floor. It scores accuracy while catching no buyers, which is why accuracy is not our metric.

One-rule (depth-1 tree) baseline

The single best split on one feature.

A meaningful baseline. In setting A it learns "PageValues > 1.1", and in B "ExitRates < 0.029". If a model can't beat one rule, it adds nothing.

Logistic regression

Linear log-odds, fitted by minimising L2-penalised log-loss. Tuned: penalty C, class weight (8 configs).

Assumes effects are additive on the log-odds scale (after log1p). Interpretable, well-calibrated, a strong simple model.

Decision tree

Recursive splits minimising Gini impurity. Tuned: depth, min leaf size, class weight (24 configs).

Captures thresholds and interactions with no scaling, but has high variance.

Random forest

300 trees on bootstrap samples (bagging) with random feature subsets, averaged. Tuned: depth, leaf, features, class weight (16 configs).

Lowers a single tree's variance, and handles skew and interactions.

Gradient boosting

Histogram-based trees added one at a time to correct earlier errors (log-loss); early stopping on part of the training data. Tuned: learning rate, leaves, L2 (8 configs).

Often strongest on tabular data, but needs more tuning and is easier to overfit.

The grids are small on purpose: 15% validation (1,849 sessions, 286 buyers) is not enough to reliably separate dozens of configurations.

5Evaluation design

Fixed before any model was compared, and kept the same for every model.

Train 70% ·
Val 15% ·
Test 15% ·

Stratified on Revenue, seed 42. Every split has 15.5% buyers. The exact row assignment is in results/splits.csv.

Protocol

  1. Fit every configuration on train and score it on validation by PR-AUC. Keep the best per model family.
  2. For each tuned model, pick the decision threshold that maximises F1 on validation.
  3. In each setting, the model with the highest validation PR-AUC is selected. This rule was declared in advance.
  4. Score every tuned model once on test at its validation threshold. Test data never influences a choice.
  5. Quantify uncertainty: 1,000-sample bootstrap of the test set for 95% CIs, and a paired bootstrap for differences between models.

What the evidence says

  1. Every learned model beats both baselines in both settings. In setting B the selected beats the one-rule baseline by PR-AUC (paired 95% CI excludes 0).
  2. PageValues carries most of the signal in setting A. A single split on it already reaches PR-AUC . Permuting it on validation lowers the selected model's PR-AUC by , against at most for any other feature. Removing it costs PR-AUC.
  3. Without PageValues, the three stronger models are statistically close. On paired bootstrap, − logistic regression = , and − random forest = . Both intervals include 0. The forest even scored slightly higher on test. We still report the validation-selected model, because switching after seeing test results would bias the estimate. 5-fold CV on train+val (§9) agrees that the gap is within noise.
  4. Interpretation of B's model: the most useful features are Month (November sessions buy most), ProductRelated_Duration and ExitRates. Logistic regression coefficients point the same way: more time on product pages raises the odds, and higher exit rates lower them. These are associations. For example, long product browsing may simply mark visitors who had already decided to buy.

Patterns

  • False positives look like buyers who didn't buy. Their median session has about as many product pages and as much product time as true positives. Behaviour alone cannot tell a careful comparison-shopper from a buyer.
  • What the model is missing is exactly PageValues. True positives have a median PageValues of , false positives have 0. Among test sessions with PageValues = 0, only of flagged sessions are buyers, against when it is > 0. This is the information gap between settings A and B.
  • False negatives are short sessions. They have about half the product pages and time of true positives, and a few look implausible: 8 purchase sessions in the full data record at most one page view. A purchase normally needs several pages, so these rows probably reflect tracking or sessionisation quirks.
  • The model leans on context. New visitors and November sessions get higher recall but also more false alarms, because the model has learned that both raise the base rate. This would hurt in a month or traffic mix that differs from the training data (see the temporal check in §9).

9Robustness checks

Extra experiments that test whether the main conclusions depend on one lucky split or a hidden choice. All are in results/extra_experiments.json.

a. 5-fold cross-validation on train + validation (test untouched)

The ranking baselines ≪ logistic regression ≈ tree < forest ≈ boosting is stable across folds. Fold-to-fold spread (SD ≈ 0.01–0.04) is about as large as the gaps between the top models. This is why we do not claim one of them is best.

b. Temporal hold-out: train Feb–Sep, threshold on Oct, test Nov–Dec

The random split mixes all months. Here the model must predict a later period whose purchase rate () is almost double the training period's ().

In setting B, logistic regression () holds up at least as well as boosting (). The flexible models' small advantage on the random split does not survive a shift in time. Lift over the base rate also shrinks, so random-split scores are optimistic for deployment.

c. Duplicates and d. analytics rates

  • Removing the 125 duplicate rows and re-splitting: setting-B test PR-AUC (vs ). The decision to keep them does not drive results.
  • Also dropping BounceRates and ExitRates (page-level analytics aggregates): best test PR-AUC . Performance barely moves: page counts and durations carry overlapping information, so the setting-B result does not hinge on those two columns.

10Limitations

  • Prediction time. Features summarise the whole session, so this is an end-of-session model. A live, mid-session system would see less information and would likely score lower.
  • PageValues uncertainty. We could not verify how Google Analytics computed it for this dataset. Setting A might be fair or might be leaky. We report both and base claims on B.
  • One store, one year, unknown site. The data has no January or April, and the codes are anonymised. The temporal check shows performance changes when the period changes, so we make no claim for other retailers.
  • Small positive class. The test set has 286 buyers, so PR-AUC CIs are about ±0.05 wide. Differences between strong models are within noise.
  • Single validation split for selection. 15% validation chose boosting, but CV slightly prefers the forest. Model selection is itself noisy at this size.
  • Data quirks. A few "purchase" sessions record at most one page view, which suggests tracking artefacts we cannot clean without raw logs.
  • No causal reading. Importance scores show what the model uses, not what makes people buy.

11Conclusion

Browsing behaviour alone predicts purchase sessions better than chance and better than a one-rule baseline, but modestly. In our main setting, PR-AUC is against a prevalence of . At a validated threshold this means catching about of buyers while two in three flagged sessions do not buy. That is useful for cheap actions such as a reminder email, but not for costly ones.

The impressive-looking PR-AUC of with all features is driven by PageValues, a revenue-derived score, and should not be read as "behaviour predicts buying". Among models, logistic regression, random forest and gradient boosting perform within noise of each other. The simplest of them was the most stable under a shift in time. For this question and data, the main lessons concern framing and leakage, not model complexity.

Possible next steps: time-stamped click data to build a genuine mid-session predictor; a cost-based threshold agreed with the business; data from more stores or years to test transfer.
